# 주문 알림음

`src/lib/sound.ts` 가 `import.meta.glob` 으로 이 폴더를 훑어서 있는 것만 쓴다.
파일을 넣거나 바꾸면 코드는 고칠 필요 없다.

## 현재 들어있는 것 (2026-10-28)

| 파일명 | 언제 울리나 | 내용 |
|---|---|---|
| `alert-delivery.mp3` | 이용방법이 **배달** | 벨 + "선결제 배달주문이에요" |
| `alert-takeout.mp3`  | 이용방법이 **포장** | 벨 + "선결제 픽업주문이에요" |
| `alert-dinein.mp3`   | 이용방법이 **매장 식사**(DB 값 `내점`) | 벨 + "선결제 내점주문이에요" |
| `order-alert.mp3`    | 위 파일이 **없는** 종류 · 미리 듣기 기본값 | 기존 알림음 |

세 파일은 **손으로 만들지 않는다.** `scripts/gen-alert-sounds.py` 가
`scripts/voice-src/` 의 녹음 원본 앞에 종소리를 붙여서 만든다:

```
python3 scripts/gen-alert-sounds.py
```

벨만 들어보려면 `scripts/voice-src/bell-preview.mp3`.
벨 음높이·길이·음량은 그 스크립트 상단 상수를 고치고 다시 돌린다.

## 음성을 다시 녹음할 때

`scripts/voice-src/` 의 `delivery.mp3` · `takeout.mp3` · `dinein.mp3` 를
**같은 이름으로** 덮어쓰고 스크립트를 다시 돌린다. 이 폴더의 `alert-*.mp3` 를
직접 바꾸면 다음 생성에서 날아간다.

지킬 것:

- **mp3.** wav·m4a·ogg 는 glob 패턴(`*.mp3`)에 안 걸린다.
- **2초 안쪽** 이면 넉넉하다. 지금 음성이 2.3초, 벨까지 2.7초다
  (예전 기본음이 3.0초였으니 그보다 짧다).
  알림 방식을 '확인할 때까지 반복' + 0.5초 간격으로 쓰는 매장이 있어서,
  길어지면 소리가 겹쳐 쌓이기만 하고 알람으로 안 들린다.
- **앞에 묵음을 두지 않는다.** 벨이 앞에 붙으니 음성은 바로 시작해야 한다.
- **세 개의 음량을 맞춘다.** 하나만 작으면 그 종류를 놓친다.
  지금 세 개가 -17.8 ~ -17.9 LUFS 로 0.1 안에 들어와 있다. 다시 녹음하면
  `ffmpeg -i <파일> -af ebur128 -f null -` 로 확인하면 된다.
- 100KB 안쪽. 번들에 base64 로 들어가므로 몇 MB 를 넣으면 앱 시작이 느려진다.

## 파일명이 틀리면

터지지 않고 **조용히 `order-alert.mp3` 로 떨어진다.** "소리가 왜 안 바뀌지" 가
되므로, 넣은 뒤 **설정 > 기타 설정 > 주문 종류별 알림음** 에서 확인한다.
버튼에 `· 기본` 이 붙어 있으면 그 종류 파일을 못 찾은 것이다.

## 왜 base64 로 번들에 박히나

프로덕션 Electron 은 `file://` + ASAR 이라 별도 에셋 파일 경로가 불안하다.
`electron.vite.config.ts` 의 `assetsInlineLimit` 가 **mp3 만** data URL 로
인라인한다(폰트·이미지는 그대로 외부 파일). 그래서 경로 문제가 없다.

바꾼 뒤 `pnpm build` 를 돌려 번들에 data URL 로 들어갔는지 보면 된다.
이 폴더의 `*.mp3` 는 **전부** 인라인되므로, 쓰지 않을 파일을 여기 두지 않는다.
