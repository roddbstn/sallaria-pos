# 주문 알림음

이 폴더에 mp3 를 넣으면 그게 알림음이 된다. 코드는 고칠 필요 없다 —
`src/lib/sound.ts` 가 `import.meta.glob` 으로 이 폴더를 훑어서 있는 것만 쓴다.

## 파일 이름 (이름이 곧 역할이다)

| 파일명 | 언제 울리나 | 녹음할 말 |
|---|---|---|
| `alert-delivery.mp3` | 이용방법이 **배달** | "선결제 배달주문" |
| `alert-takeout.mp3`  | 이용방법이 **포장** | "선결제 포장주문" |
| `alert-dinein.mp3`   | 이용방법이 **매장 식사**(DB 값 `내점`) | "선결제 내점 주문" |
| `order-alert.mp3`    | 위 파일이 **없는** 종류 · 설정의 미리 듣기 기본값 | (지금 쓰는 소리) |

이름이 하나라도 틀리면 그 종류는 조용히 `order-alert.mp3` 로 떨어진다.
터지지 않고 "소리가 왜 안 바뀌지"가 되므로, 넣은 뒤
**설정 > 기타 설정 > 주문 종류별 알림음** 에서 확인한다.
버튼에 `· 기본` 이 붙어 있으면 그 종류 파일을 못 찾은 것이다.

## 만들 때 지킬 것

- **mp3.** wav·m4a·ogg 는 glob 패턴(`*.mp3`)에 안 걸린다.
- **1.5초 안쪽.** 알림 방식을 '확인할 때까지 반복'으로 두고 간격을 0.5초로 쓰는
  매장이 있다. 소리가 길면 다음 소리와 겹쳐 쌓이기만 하고 알람으로 안 들린다.
- **앞에 묵음을 두지 않는다.** 재생 시작과 소리 시작 사이가 비면 피크타임에
  "울렸나?" 가 된다.
- **세 개의 길이와 음량을 맞춘다.** 하나만 작으면 그 종류를 놓친다.
- 파일 크기는 신경 쓰지 않아도 된다(지금 기본음이 48KB). 다만 번들에 base64 로
  들어가므로 몇 MB 짜리를 넣으면 앱 시작이 느려진다 — 100KB 안쪽이면 넉넉하다.

## 왜 base64 로 번들에 박히나

프로덕션 Electron 은 `file://` + ASAR 이라 별도 에셋 파일 경로가 불안하다.
`electron.vite.config.ts` 의 `assetsInlineLimit` 가 **mp3 만** 강제로 data URL 로
인라인한다(폰트·이미지는 그대로 외부 파일). 그래서 경로 문제가 없다.

바꾼 뒤에는 `pnpm build` 를 한 번 돌려서 번들에 data URL 로 들어갔는지 보면 된다.
