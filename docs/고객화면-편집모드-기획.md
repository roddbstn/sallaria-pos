# 고객 화면 '화면 편집' — 사이드패널 기획

작성 2026-10-19. 대상: 고객 화면(`src/pages/Customers.tsx`)의 `typeEditMode`.

---

## 지금 상태

'화면 편집 ✎'을 누르면 **바뀌는 게 두 가지뿐**이다.

1. 우상단 버튼이 `편집 취소` / `완료`로 바뀐다
2. 유형 필터 pill 에 연필 아이콘이 붙고 `+ 유형 추가`가 생긴다

우측 사이드패널(고객 현황)은 **그대로다.** 편집 중인데 옆에서는 통계가 돌아가고 있다.

메뉴 화면은 다르다. 편집에 들어가면 **사이드패널이 통째로 편집 패널로 바뀌고**,
그 아래 64px짜리 `취소` / `완료` 버튼 쌍이 붙는다. 두 화면의 같은 이름 버튼이
다르게 동작하는 셈이다.

---

## 무엇을 넣을지 — 고르는 기준

아무거나 넣으면 안 된다. 세 가지를 통과한 것만 넣는다.

1. **이 화면에서만 할 수 있는 일인가** — 계정 추가·충전처럼 다른 경로가 있는 건 뺀다
2. **되돌릴 수 있는가** — `취소`를 누르면 원래대로 돌아와야 한다. 즉시 반영되는 건 편집이 아니다
3. **점주가 실제로 바꾸고 싶어 하는가** — 지금 화면에서 불편을 겪는 지점인가

## 사이드패널 구성

편집에 들어가면 고객 현황 자리에 이 패널이 들어온다.

```
┌─ 화면 편집 ─────────────────┐
│                             │
│  계정 유형                   │
│  ┌─────────────────────────┐│
│  │ ⠿  부서        ●  ✎  🗑 ││
│  │ ⠿  기업        ●  ✎  🗑 ││
│  │ ⠿  개인        ●  ✎  🗑 ││
│  └─────────────────────────┘│
│  + 유형 추가                 │
│                             │
│  표에 보일 칸                │
│  ☑ 유형    ☑ 추이           │
│  ☑ 이용자수 ☑ 잔액          │
│  ☐ 이번달 선결제             │
│                             │
│  기본 정렬                   │
│  [등록순] [잔액순] [주문순]   │
│                             │
│  ┌──────────┬──────────┐    │
│  │   취소    │   완료    │    │
│  └──────────┴──────────┘    │
└─────────────────────────────┘
```

### ① 계정 유형 — 이미 하던 일을 제자리로

지금은 **표 위 pill 에 연필이 붙는** 방식이다. 유형이 6개까지 늘 수 있는데
pill 줄에서 이름을 고치고 순서를 바꾸면 줄이 흔들려서 조작이 어렵다.

패널로 옮기면 세로 목록이라 **드래그 순서 변경**이 자연스럽고, 색 지정도 한자리에서 된다.
`stores.customer_types` 는 이미 배열이라 순서가 곧 노출 순서다.

### ② 표에 보일 칸 — 가장 수요가 분명하다

지금 표는 `순번 · 계정 이름 · 유형 · 추이 · 이용자수 · 잔액 · 이번달 선결제` 7칸 고정이다.
매장마다 안 쓰는 칸이 있다 — 1인 거래처만 있는 매장은 '이용자수'가 늘 1이고,
충전을 분기로 받는 매장은 '이번달 선결제'가 늘 0이다.

**근거 (침산점 활성 계정 25곳 실측, 2026-10-19):**

| 칸 | 비어 있는 계정 | 비율 |
|---|---|---|
| 이용자수 (1명 이하) | 12곳 | **48%** |
| 이번달 선결제 (0원) | 21곳 | **84%** |

이번달 선결제 칸은 **다섯 중 넷이 빈 칸**이다. 충전을 월초에 몰아 받는 구조라
월 중순 이후로는 대부분 0 으로 깔린다. 그 칸이 141px 를 쓰고 있다.

칸을 줄이면 계정 이름이 넓어진다. 가장 긴 계정 이름이 16자인데 지금은 잘린다.

- 계정 이름과 순번은 끌 수 없다 — 끄면 행을 식별할 수 없다
- 저장 위치는 `stores` 에 `customer_table_columns jsonb` 한 칸

### ③ 기본 정렬 — 가볍지만 매번 바꾸는 일

지금은 `created_at` 오름차순 고정이다. 잔액이 적은 곳부터 보고 싶은 점주는
매번 눈으로 훑는다. 기본값을 고를 수 있게 한다.

## 안 넣는 것과 이유

**계정 추가·삭제** — 편집 모드에 두면 `취소`가 무엇을 되돌리는지 모호해진다.
계정을 지우고 '취소'를 누르면 되살아나야 하나? 즉시 반영되는 일은 편집 모드에 두지 않는다.

**사이드패널 지표 고르기** — 재귀적이다(편집 패널에서 그 패널 자신을 편집).
수요도 확인되지 않았다.

**비활성 계정 표시** — 이미 상시 토글이 있다. 같은 일을 두 곳에 두면 어느 쪽이
이기는지 설명해야 한다.

---

## 동작 규칙

- **취소** — 패널에서 바꾼 것 전부 버린다. 유형 이름·순서·칸·정렬 모두 원래대로
- **완료** — 한 번에 저장한다. 유형은 `stores.customer_types`, 칸·정렬은 새 컬럼
- 편집 중에는 **표의 행 클릭을 막는다** — 계정 상세가 열리면 편집하던 패널이 덮인다
- 저장 실패 시 편집 모드를 유지하고 패널 안에 이유를 띄운다. 닫으면 작업이 사라진다

## 열어둔 질문

- 유형 **색**을 점주가 직접 고르게 할지, 지금처럼 팔레트에서 자동 배정할지.
  직접 고르게 하면 비슷한 색을 골라 구분이 안 되는 일이 생긴다
- 칸 설정을 **매장별**로 둘지 **기기별**로 둘지. 지금 구조상 매장별(`stores`)이 자연스럽지만,
  한 매장에 POS 가 두 대면 서로 다른 칸을 보고 싶을 수 있다
